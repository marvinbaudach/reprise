# Drop phone sync for podcasts and YouTube — implementation report

Implemented on `feature/drop-phone-sync-for-podcasts-and-youtube`, surveyed and
developed from the requested base `79ba78c227` without rebasing onto later
`origin/dev` movement. No push was performed.

## Packages and commits

- P1 — `df290a22c3 refactor(gnome): reduce device sync to playlists`
  - Reduced the device page, target browser, picker, summaries, handlers, and
    storage composition to one playlists target.
  - Removed category switches, size-cap controls/readings, YouTube and podcast
    segments, and the one-entry legend.
  - The category bar remains distinct from the compact `StorageBar`: it owns
    the Music/Other/Free composition plus the hatched incoming band and the
    before/after free-space projection. They were not merged.
- P2 — `ae42cdf8ae refactor(gnome): remove podcast phone sync actions`
  - Removed episode/source/channel phone menus, per-device choices, action
    dispatch, badges, groups, sort state, and worker round trips.
  - Preserved ordinary offline Download and Load More replay; `NET-3c` now
    describes only those surviving transient actions.
- P3 — `156b8bc79e refactor(mcp): drop episode phone sync action`
  - Removed `want_on_device`, its parameter and implementation from the MCP
    episode mutation schema and description.
  - Kept `download` and `remove`; the former action is covered as an unknown
    action instead of being silently accepted.
- P4 — `8e9d4969b9 docs(sync): make playlists the sole phone target`
  - Added active MTP-54, rewrote MTP-22/23/27/33/37/45/51, and retired the
    subscription, cap, and preparation rules against MTP-54.
  - Also retired MTP-25 and MTP-42 through MTP-44 because their cap/preparation
    subjects disappeared with the code, although the supplied rule list did
    not name them.
  - Updated the maintained Android-sync plan status and all seven gettext
    catalogues. `SPEC.md` does not exist at the surveyed base.
- P5 — `f8ffd0d3e5 refactor(sync): keep phone sync playlist-only`
  - Deleted `SyncTargetKind`, cap eviction, podcast/YouTube device planning,
    subscription selection, wanted-on-device state, queued device downloads,
    and preparation phases.
  - Made Core, GNOME, reprise-view, runtime protocol, MCP DTOs, MPRIS, Linux
    inspection/browser code, and the fake backend consume one `SyncTarget` and
    one `DeviceTargetSnapshot`.
  - Added migration v68. It removes subscription targets and their local
    inventory claims, rebuilds `device_sync_targets` with `device_serial` as
    its sole primary key and no kind/cap columns, drops
    `podcast_subscription_devices`, drops `wanted_on_device`, and leaves phone
    files untouched. A current-v68 database is a no-op.
  - Removed the dead Preferences source-module replan hook and obsolete
    MTP-46 CUA/architecture contract. The Android-sync CUA scenario now checks
    that the removed rows and cap copy are absent.

## Display and visual verification

The exact Xvfb-backed GTK test
`mtp_13_full_page_renders_and_wires_only_the_playlist_mirroring_controls` ran
as **1 passed, 0 failed**. It asserts a Playlists surface and the absence of
YouTube audio, Podcast episodes, size-limit copy, and the removed library/file
controls.

The fake-phone CUA journey was attempted twice with private X11, D-Bus,
disposable XDG state, fake audio, and no live library. It reached the app and
captured the initial window, but the private AT-SPI snapshot degraded with
`A connection to the bus can't be made`; therefore it could not navigate to
the device page. No device-page screenshot is claimed, and the result remains
visually unverified. A physical-phone pass is also still manual.

## Decisions and residual risk

- `NET-3c` was narrowed rather than retired because normal offline Download
  and Load More replay still exists.
- Historical migration columns and compatibility migrations that the v68
  specification did not order removed were left in place; current code has no
  podcast/YouTube phone-sync consumer.
- Files already under `/Music/Reprise-YouTube` or `/Podcasts/Reprise` are not
  touched. Only their stale local inventory rows are removed.
- The remaining risk is visual layout on a real device page because AT-SPI
  prevented the requested CUA screenshot; the isolated GTK widget contract is
  green.

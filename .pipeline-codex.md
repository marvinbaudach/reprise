## Readout ownership

The displayed readout now carries its own semantic tone. A resting blocked
verdict is failed, a passing check name is neutral, and a failed check name is
failed. The CSS keys off that tone rather than the gate strip's aggregate
blocked state, so another failed check can no longer colour a passing peek.

`show-8` can reach this behavior at the existing pure readout seam and through
the source stylesheet. It asserts the passing-peek, failed-peek, and resting
blocked cases and rejects the old aggregate-state selector.

## Pointer and focus peeks

Pointer and focus peeks use separate state, with keyboard focus taking
precedence and pointer hover as its fallback. A captured scroll schedules one
post-layout animation frame and clears only the pointer peek when its remembered
tick no longer matches `:hover`. This was chosen over clearing the shared
readout on every scroll because a keyboard-focused tick must remain announced;
focus also wins if a parked pointer and keyboard navigation temporarily name
different checks.

No regression assertion was added for finding N. The Showroom tests inspect
source and built output but do not run a browser, so they cannot reproduce the
necessary sequence: establish real hover, scroll layout beneath a stationary
pointer, observe CSS drop `:hover` without `mouseleave`, then inspect the live
region. A source assertion for the names of two state variables or a scroll
listener would not prove that behavior and could pass while the interaction
remained broken. The implementation is typechecked and linted but was not
claimed as browser-reverified in this pass.

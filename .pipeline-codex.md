# Location is not a Concerts setting — implementation report

## Packages

- **A — app-wide foundation** (`1f19104ce5`): renamed the default-radius key cleanly to `location.default_radius_km`, moved the radius API and presets into the app-wide Location domain, and introduced an ungated weak-subscriber location broadcast used by Concerts without depending on `ConcertsRuntime`.
- **B — Preferences Location** (`383f09fb15`): added the Location main page between Library and Plugins, moved all city, portal, clear, geocoding, and default-radius controls there, connected every write to the app-wide broadcast, listed the three real readers, and used the shipped `find-location-symbolic` icon after resolving it through the icon guard test.
- **C — Concerts reference** (`5085e66324`): removed Concerts-owned city and radius controls and added the first, read-only Location reference row with missing/stored copy, a Location deep link, and immediate broadcast refresh.
- **D — deep link** (`f1b4b1654a`): made the Location deep link open or retarget the Location main page, focus City, and highlight it briefly only when the value is missing.
- **E — honest no-location behavior** (`1718642661`): made radius inactive without a location, added the `off` and city-named chips, corrected counts through the single facet-activity seam, added the all-concerts banner, temporarily removed Distance from the view/editor/sorter without changing persisted choices, restored exact visibility and sorting when Location returns, gave Venue the freed width, and added Radio's two honest empty states with automatic broadcast resumption.
- **F — rules and proof** (`this commit`): updated SET-10, added SET-15, rewrote CONC-2 and RAD-5, retained SRC-19's locale fallback while linking it to Location, strengthened clear/gate/query/facet regressions, renamed the Location ownership tests for rule traceability, and captured the seven required visible states plus rollback controls.

The separate plan-handoff commit `9a5999e842` was already present during execution; it records that E2b's city-named chip belongs to this plan and is not one of packages A–F.

## Deviations

There are no product deviations from the requested scope. In particular:

- there is no migration, old-key reader, compatibility fallback, or deprecated setting path;
- Podcasts received no empty state and SRC-19's locale fallback is unchanged;
- `concerts.filter.radius_km` remains view state while only the default radius moved;
- no `po/*.po` file was edited by hand;
- no real database, cache, music library, desktop session, account, or external service was used;
- no push, pull request, merge, or production promotion was performed.

The clean-tree merge-readiness wrapper was not run because its scratch/integration workflow would write outside the user-authorized worktree. Its individual substantive gates were run in this worktree instead.

## Questions answered during implementation

- **Where should the broadcast live?** In toolkit UI state beside the window, with the existing weak-subscriber shape. This is reachable by Radio and Preferences and carries no Concerts or online gate.
- **What survives Clear?** Everything except the four Location identity keys. Default radius, Concerts view filters, module choices, and the online-source choice are preserved and tested.
- **What does a countryless portal location say?** The dedicated `Location has no country` state and its exact explanatory text; it never claims no location exists.
- **How is hidden Distance state preserved?** Automatic availability is an in-memory presentation constraint layered over stored visibility and sort. It never persists the temporary hide, and restoration reads the exact prior values.
- **Which column receives the width?** Venue. Adversarial review caught an initial City-column expansion and corrected it before package E was committed.
- **Does Add Station survive Preferences?** Yes. Both an isolated display regression and observed CUA open/close evidence prove that the underlying dialog remains live.
- **Does Podcasts change behavior?** No. Only its Used by wording changed; the SRC-19 country/locale resolution remains intact.
- **What happens when the active location has no display name?** The Concerts chip falls back to the radius-only label, as specified.

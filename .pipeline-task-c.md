# Slice C — the three surfaces that show the spectrogram

Today the phone's seek bar draws `sin(x / 24dp · 2π)` under the playhead
(`WavySliderTrack` in `NowPlayingSheet.kt`) — a wave computed from nothing, which
looks like data and measures no audio. It goes.

## The contract with slice B — assume it exactly, do not write it

```kotlin
package de.reprise.spike

/** One shaped seek-bar cell, coloured in Rust so both frontends share one axis. */
internal data class TrackRenderBar(
    val silence: Boolean,
    val level: Float,
    val red: Float,
    val green: Float,
    val blue: Float,
)

internal interface TrackRenderDataPort {
    /**
     * Bumped whenever rendering data has newly landed for any track. Read it
     * before asking for bars so a surface recomposes when an analysis finishes.
     */
    val revision: Int

    /** `null` means "not analysed" — the flat bar. An empty list means analysed and empty. */
    fun bars(trackId: Long, barCount: Int): List<TrackRenderBar>?

    /** The 24 stored band bytes (0..255) nearest `position` in 0..1, or `null` when unanalysed. */
    fun spectrumColumn(trackId: Long, position: Float): List<Int>?
}

/** Previews and any surface without an activity draw the flat bar. */
internal object NoTrackRenderData : TrackRenderDataPort {
    override val revision = 0
    override fun bars(trackId: Long, barCount: Int): List<TrackRenderBar>? = null
    override fun spectrumColumn(trackId: Long, position: Float): List<Int>? = null
}

internal val LocalTrackRenderData =
    staticCompositionLocalOf<TrackRenderDataPort> { NoTrackRenderData }
```

## 1. The seek bar

Replace the invented wave with the real thing. `bars(trackId, barCount)` where
`barCount` is what fits the width; each bar is a silence dot or a level, in its
own colour. The desktop's rendering is the reference — read
`crates/reprise-gnome/src/ui/player_bar/waveform_seek_render.rs` for what it
does with `DisplayBar::Silence` (a fixed 2 px dot, `SILENCE_DOT_HEIGHT`) and with
levels, and follow it in Compose rather than inventing a second look.

**`bars(...) == null` is the flat bar** (decision 1): a plain line, no wave, no
shimmer, nothing that implies data. It is what an unanalysed track looks like and
it must be visibly plainer than an analysed one, not a low-amplitude version of
it.

The playhead keeps working exactly as it does now — the seek gesture, the elapsed
time in teal, the `−m:ss` remainder, and the scrub behaviour M9a proved are not
yours to change.

## 2. Spectrum, at the cover

The visualiser named `Spectrum` in the switcher: the column of the current
moment, `spectrumColumn(trackId, position)` — 24 band bytes, 0..255 — drawn over
the cover. Position is the playback fraction in 0..1.

Derived from the desktop rather than invented (decision 5): the same 24
logarithmic bands, coloured on the same axis. A band's byte is its level; use the
band's own position on the spectral axis for its colour, so the low end sits at
the coral end and the top at teal — the same rule the seek bar follows.

## 3. Preview band

The visualiser named `Preview`: the seek bar's own rendering, without playhead,
without times, as a quiet band under the cover. It is the same `bars(...)` data
at whatever width it has.

## 4. The two entries stop lying

`AppearanceSettingsPage.kt` shows *Spectrum* and *Preview* disabled with "Needs
track analysis". That is now a **per-track** truth, not a permanent one: with
data for the playing track they are selectable, without it they are not, and the
reason stays the same sentence. The long-press menu on the Now Playing surface
(`NowPlayingVisualizer.kt`) shows the same four entries and must agree — M9b's
rule that this is one value with one disabled state still binds.

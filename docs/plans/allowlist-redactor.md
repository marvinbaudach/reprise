# Allowlist redactor for the diagnostics report (#1335, replaces PR #1374)

## Goal

The copied diagnostics report, and the run log it is built from, carry only text that is
provably harmless. Text is harmless when it was compiled into the binary (the app's own
log templates, the standard library's panic phrases, static panic payloads, targets,
levels, field keys, callsite locations, backtrace symbols), when it is a typed number, or
when it is the value of a typed field whose key is in `KEEP_FIELDS`. Everything else
becomes `…`. No heuristic decides where a name, a path or a secret ends, because nothing
is searched for any more.

Owner decision of 2026-11-22 (`docs/plans/HANDOFF-2026-11-22-redactor-round4.md`): PR #1374
(round 4, `9ced953d8f`) is not landed; its worktree `.worktrees/redactor-leaks` stays as a
read-only reference. Threat model unchanged from #1335: a user pastes the Copy Diagnostics
output or the run log into a public issue.

## Decisions (grill, 2026-11-22)

1. Templates come from a **checked-in table keyed by source file**, generated by the
   existing test-only token scanner and enforced by a freshness test with a bless command
   (not `build.rs`, not `name:` on every call).
2. A **placeholder is always `…`**, numbers included. Numbers survive only as typed
   fields; the runtime-hole call sites whose value is a number become fields here.
3. **Text values of `KEEP_FIELDS` keys stay**, behind the existing value-shape check; the
   PR body names the residual (`state=Pink`). Foreign callsites show no fields.
4. Lines from own code end with the callsite as **`@ crates/<crate>/src/….rs:<line>`**,
   in the run log and in "last warnings". Foreign lines read `<ts> <LEVEL> <target>: …`.
5. The run log is **renamed** to `run.log`/`run.log.1`; the first instance deletes the old
   `reprise.log`/`reprise.log.1` once; FB-19 and START-6 follow.
6. Crash message: a **static payload is kept**; a formatted one is matched against a
   curated std-phrase table **and** the templates of the panic location's file; else `…`.
   Location and symbols stay, build paths shortened to `…/<crate>-<ver>/src/…`.
7. `invariant_broken!` forwards the caller's literal with `concat!`; its `({}:{})` suffix
   goes (decision 4 shows the site).
8. Acceptance: a corpus from the round-3/4 probes plus the round-4 review findings with
   `zqx` needles, an invariant fuzz and an end-to-end test. The 152 tests of
   `fix/redactor-leaks` are not carried over (they test deleted code).
9. Branch **fresh from `dev`**. PR #1374 is closed unmerged with a pointer once the new PR
   is open; the new PR closes #1335.
10. **One strand** (see `## Parallelität`).

## The invariant

Every byte of the report's log sections ("last warnings", "log, this run", "log, previous
run", the crash section) is one of:

1. **static text**: a template from the template table with every hole replaced by `…`; a
   standard panic phrase from the phrase table, reduced the same way; a `&'static str`
   panic payload; a tracing target or level; a field key; an own callsite location; a
   backtrace symbol name; a source location in the location grammar (D6); the report's
   own labels and markers;
2. **a typed number or bool**: a field recorded through `record_i64`, `record_u64`,
   `record_i128`, `record_u128`, `record_f64` or `record_bool`, under a `KEEP_FIELDS` key;
3. **a policy-trusted value**: a `KEEP_FIELDS` value recorded through `record_str` or
   `record_debug` that passes the value-shape check (number, plain identifier, option,
   tuple variant or list of those, `version` dots);
4. **a timestamp** written by our own clock, or the numbers of a location or a frame;
5. the markers `…` and `$REDACTED`.

The rendered message of an event is never copied into the output. It only selects which
static template stands in for it. A stale table, a forged line or a wrong match can
therefore only ever show the wrong static template, never user text.

Category 3 is the one place where the guarantee rests on review rather than construction:
`KEEP_FIELDS` is enforced by key, not by value type (`field_policy.rs` says so). The owner
accepted typed `KEEP` fields as harmless; the shape check stays as defense in depth.

## Design

### D1. A message is its callsite's static template

At record time the layer has the event's `Metadata`: `file()`, `line()`, `target()`,
`level()`, all `'static` for a static callsite. For a callsite whose `file()` appears in the
template table, the rendered message is matched against that file's templates: a template
matches when its literal pieces occur in order and cover the message from start to end,
holes matching any text, the empty text included. The output is the reduced form of the
matching template with the most literal characters (ties broken by table order). No
template matches, or the file is not in the table: the message is `…`.

Holes are always `…`, also when their text is a number (decision 2). The runtime-hole
sites whose value is a number move that value into a typed field.

Why keyed by file and not by `file:line`: a checked-in table keyed by line would go stale
with every edit above a log call. Keyed by file, it changes only when a log text is added,
changed, removed or moved to another file. A same-file collision can only pick the wrong
static template, which the invariant tolerates.

### D2. The template table

- **Generator**: the field sweep (test-only, `reprise-core/src/diagnostics/field_sweep*.rs`)
  also returns the message literal of every event site, unescaped as Rust reads it (plain,
  raw `r#"…"#`, `\` line continuation, `\n`, `\t`, `\\`, `\"`, `\'`, `\0`, `\x..`,
  `\u{…}`), and the first literal argument of every `invariant_broken!` site, prefixed
  `invariant broken: `. Format strings are parsed with `{{`/`}}` unescaped and every
  `{…}` a hole; a malformed one fails the test with the site.
- **Data file**: `crates/reprise-core/src/diagnostics/log_templates.txt`, one line per
  distinct `(file, template)`: `<workspace-relative file>\t<template>`, with `\\`, `\t` and
  `\n` escaped, sorted, no duplicates. Data, not code, so the 800-line cap does not apply.
- **Freshness test** (`log_templates_tests.rs`): the file equals the generator's output.
  On a mismatch it names every missing and every stale line and the bless command. An
  `#[ignore]`d test `bless_log_templates` rewrites the file. Adding or changing a log
  text therefore fails `cargo test --workspace` until the table is regenerated, and the
  table's diff shows the reviewer exactly which new text can leave the machine.
- **Runtime**: `log_templates.rs` parses the `include_str!`ed file once (`OnceLock`) into a
  per-file index of parsed templates. A malformed line is skipped at run time and fails
  the freshness test.
- **Canary**: a test in each crate whose events reach the desktop layers (core, view,
  platform-linux, gnome) asserts that `file!()` has the table's path form
  (`crates/<crate>/src/…`), so a build configuration that changes the form fails a test
  instead of silently turning every message into `…`.

### D3. Typed fields

One visitor records each field with its kind: `Int`, `Uint`, `Float`, `Bool` (the typed
`record_*` methods, overridden), `Str` (`record_str`) or `Debug` (`record_debug`,
`record_error`). The `message` field fills the message slot as today (the classification
test still refuses an explicit `message =` field). For an own callsite (its file is in the
table): a `KEEP_FIELDS` key keeps a typed number or bool as written and keeps `Str`/`Debug`
text only when it passes the value-shape check (today's `is_kept_number` and
`redact_composite` rules, moved to one `field_values.rs`); any other key is
`key=$REDACTED`. A foreign event shows no fields at all: its keys are not classified and
its values are foreign.

`panic_payload` and `panic_location` move from `KEEP_FIELDS` to `REDACT_FIELDS`: the crash
section carries their reduced forms (D6).

### D4. The safe line

The core function `safe_event(callsite, recorded) -> SafeEvent` is the only producer of log
text for the report and the run log. `SafeEvent::line()` gives

```
2026-11-22T10:00:00.123Z  WARN reprise::ui::sidebar: could not rebuild the sidebar; track_id=7 error=$REDACTED @ crates/reprise-gnome/src/ui/sidebar/sidebar_rebuild.rs:30
```

The `@ file:line` suffix is the callsite's static location, shown for own callsites only.
A line feed inside a template is written as the two characters `\n`, so one event is
always one line. Foreign events read `<ts> <LEVEL> <target>: …` (bridged `log` records have
the target `log`). "last warnings" keeps its `HH:MM:SS <segment>: ` shape and gains the
same suffix.

### D5. Run log, session warnings and the report

- `FileMirrorLayer` writes `SafeEvent::line()`. `SessionDiagnosticLayer` stores the reduced
  message, fields and location in `DiagnosticEvent`. Neither holds a `RedactionContext`.
- `render_report` embeds the session events and the log tail lines as they are: they were
  safe when written. `redact_log_message` and the `RedactionContext` parameter go.
- **The run log changes its name**, so a file written by an earlier version (heuristic
  lines) is never read into a report: `reprise.log`/`reprise.log.1` become
  `run.log`/`run.log.1` in the same state directory. The first instance removes the two old
  files once at start (state directory only, `NotFound` ignored). The writers of the run
  log stay exactly two: `file_log` (through `FileMirrorLayer`) and
  `crash_report::write_report`.
- `invariant_broken!` forwards the caller's literal to tracing with
  `concat!("invariant broken: ", $fmt)` instead of a pre-formatted `{message}`, and drops
  its own `({}:{})` suffix. Its `debug_assert!` keeps the same text. `file!()` in a
  `macro_rules!` expansion is the outermost invocation, so the callsite's file is the use
  site, which is where the generator files the template; a test proves it.

### D6. The crash section

The panic hook already distinguishes the payload: a `&'static str` payload is what std
creates for a panic whose message has no runtime arguments, a `String` payload is a
formatted one. `write_report` takes that distinction, the `Location<'static>` and the
`Backtrace` itself instead of three strings, and writes the section already reduced:

- **message**: `Static` is kept (line feeds escaped, capped at 1 KiB). `Formatted` is
  matched against the panic phrase table (`diagnostics/panic_phrases.rs`, templates such
  as ``called `Option::unwrap()` on a `None` value``, ``called `Result::unwrap()` on an `Err`
  value: {}``, `index out of bounds: the len is {} but the index is {}`,
  `already borrowed: BorrowMutError`, `already mutably borrowed: BorrowError`, the
  overflow phrases, ``assertion `left == right` failed\n  left: {}\n right: {}``, the
  `str` slicing phrases) and against the templates of the location's file in the template
  table (which covers `invariant_broken!`'s `debug_assert!`), and reduced like D1; no
  match gives `…`. Any other payload type gives `non-string panic payload`. Every phrase
  has a test that triggers the real panic under `catch_unwind`, captures the payload and
  asserts the reduced form, so a toolchain that rewords a phrase fails a test.
- **location**: `<path>:<line>:<col>` where the path is kept when workspace-relative
  (`crates/<crate>/src/….rs`, segments `[a-z0-9_]+`), kept when `/rustc/<hex>/library/….rs`,
  shortened to `…/<name>-<semver>/src/….rs` when it contains that crate-source shape
  (registry, vendor or Flatpak build path), else `…`.
- **backtrace**: `Backtrace::to_string()` is parsed line by line; a frame line
  `<n>: <symbol>` is kept when the symbol uses only Rust-symbol characters (letters,
  digits, `_ : < > { } ( ) [ ] & * , ; ' ! -` and space), an `at <path>:<l>:<c>` line
  goes through the location grammar, any other line becomes `…`. The values are real
  symbol names, so the grammar is defense in depth; the message cannot forge a frame
  because the raw message is never written.
- `time`, `version`, `schema` and the markers stay. `crash_section_of`/`read_log_tail`
  keep their bounds and read the section as written.

Foreign panics therefore show their static payload or a reduced std phrase, their location
as `…/<crate>-<ver>/src/…`, and their symbols.

### D7. What is deleted

`redact.rs` (`redact_log_message` and everything under it), the free-text half of
`redact_assignments.rs`, `redact_path_tests.rs`, the free-text cases of
`redact_assignment_tests.rs` (the value-shape cases move with `field_values.rs`),
`RedactionContext` and `reprise_platform_linux::diagnostics::redaction_context()`,
`crash_report::scrub_directories`, and the `field_policy.rs` paragraphs about the text pass
(D2 of the old policy). `redact_composite.rs` stays, under `field_values.rs`.

## Answers to the handoff's open questions

1. **How static templates are recognised**: by the callsite's `Metadata::file()` and a
   checked-in, test-enforced table of that file's format-string literals (D1, D2).
2. **Foreign-crate messages and panics**: level, target and `…`, no fields; panics keep a
   static payload or a reduced std phrase, a shortened location and the symbols (D4, D6).
3. **How the crash section stays useful**: location, symbols and std phrases survive; only
   formatted panic text outside the phrase table and the location file's templates becomes
   `…` (D6).
4. **Round-3/4 tests and harnesses**: the 152 tests on `fix/redactor-leaks` assert the
   output of code that is deleted, and the scratch crates under
   `~/.cache/reprise-scratch/pr1374-*` assert nothing (they print observations; the oracle
   is the `zqx` canary). What carries over is the **corpus** and the **canary oracle**:
   the probe inputs (`~/.cache/reprise-scratch/logs/pr1374-r{3,4}review-probes/`) and the
   round-4 review's findings become a fixture, run through every position (Task 9).
5. **Branch**: fresh from `dev`. Of the 5.5k-line branch diff only ideas survive (the
   strict location shapes of `crash_section.rs`, the one-line message), and they are
   rewritten for the new inputs.

## Tasks (test-first; each task: failing test, minimal code, green, focused commit)

   pieces and holes; `reduced()`; anchored `matches(rendered)` with holes matching any
   text (iterative greedy-star, no recursion). Tests: escapes, adjacent holes, empty
   holes, a hole whose text contains the next literal, no match, malformed strings.

5. **Safe event** (`diagnostics/safe_event.rs`): `safe_event`, `SafeEvent::line()`, own
   versus foreign callsites, line-feed escaping, the `@ file:line` suffix.

   `ui/invariant.rs`): the kind-aware visitor, both layers on `safe_event`, the

## Parallelität

**Not cut: one strand.** Reasons:

- The template engine (Tasks 1–3) is the precondition of both halves of the work: the log
  lines (Tasks 5–7) and the crash path (Task 8), whose std phrases and location-file
  templates are matched by the same engine. A crash strand without it would need a second
  matcher.
- Deleting the heuristic redactor (Task 10) edits `render.rs`, `crash_report.rs`,
  `file_mirror.rs` and `reprise-platform-linux/src/diagnostics.rs`, which belong to both
  halves; whichever strand landed first would either break the other's build or leave the
  deletion to a third change.
- `reprise-gnome/src/main.rs` (hook) and `field_policy.rs` (`panic_*` keys) are touched by
  the message and the crash work alike.

# My Stats gets its own symbol

**Status:** in progress
**Branch:** `feature/sidebar-stats-icon`

## Problem

In the sidebar, **Queue** and **My Stats** carry the same symbol, while
**Radio** carries the same one as **Music**. This is not a design decision but
a missing asset:

- `sidebar_presentation.rs` (`NavIcon::icon_name`) asks for
  `reprise-stats-symbolic` for `MyStats` and `reprise-radio-symbolic` for
  `Radio`.
- `NavIcon::fallback_icon_name` answers with a system name for both:
  `view-list-symbolic` (the Queue symbol) and `audio-x-generic-symbolic` (the
  Music symbol), respectively.
- `nav_icon` (around line 390) chooses through
  `theme.has_icon(icon.icon_name())`. Both application symbolics are installed
  only through `data/icons/hicolor/symbolic/apps/` and, unlike
  `reprise-lyrics-symbolic` and `reprise-visual-bars-symbolic`, are **not
  embedded in the GResource**. Every non-installed run therefore always uses
  the fallback.

Measured on 2026-08-15: on this machine, neither
`reprise-stats-symbolic` nor `reprise-radio-symbolic` exists under
`~/.local/share/icons/hicolor/symbolic/apps/`; only `first-aid` and
`stethoscope` exist. The user's screenshot therefore shows
`view-list-symbolic` twice.

The existing Stats geometry is also drawn for the wrong use size:
`stats_symbolic_svg()` in `scripts/lib/brand_sources.py` works on the 24-unit
grid, while the sidebar draws the icon at `ICON_WIDTH = 16`. Two-unit axes and
a trend line with points consistently land on half pixels at 16 px. The
rendered and inspected result is grey and unreadable.

## Goal

1. `MyStats` and `Radio` show their own symbols in every run, installed or not.
2. The Stats geometry is drawn on the grid at which it is rendered.
3. No fallback disguises an error as a different feature's symbol.

## Out of scope

- `io.github.marvinbaudach.Reprise-first-aid-symbolic` remains unchanged in
  `GUARDED`: this icon is deliberately installed only, and its fallback
  (`system-search-symbolic`) is an intentional reduction rather than a
  mistaken identity.
- The palette, brand mark, and every raster graphic remain untouched.

## Tasks

The file lists are starting points, not fences: neighbouring files may be
adjusted minimally and named in the commit message. Stop only if this plan's
contract is wrong.

### Task 1 — Put Stats geometry on the 16-unit grid

**File:** `scripts/lib/brand_sources.py`

Replace `stats_symbolic_svg()`. The new geometry has already been designed and
checked at 16 px: axes at the left and bottom, three ascending bars, and every
edge on an integer coordinate. Copy it literally:

```python
def stats_symbolic_svg():
    return '''<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 16 16"
     width="16" height="16" fill="currentColor">
  <!-- Palette-independent symbolic geometry generated by the brand pipeline.
       On the 16-unit grid, not the 24-unit grid the other symbolics use: this
       glyph is a one-unit axis and three bars, and the sidebar draws it at
       ICON_WIDTH = 16. A 24-unit drawing puts every one of those edges on a
       half pixel and the icon renders as grey mush — the same reason
       hinted_16_body exists for the mark. -->
  <rect x="2" y="2" width="1" height="12"/>
  <rect x="2" y="13" width="11" height="1"/>
  <rect x="4" y="9" width="2" height="4"/>
  <rect x="7" y="6" width="2" height="7"/>
  <rect x="10" y="3" width="2" height="10"/>
</svg>
'''
```

Do not add `rx`: rounding a one-unit-wide rectangle turns it into a capsule
and blurs exactly the pixel edges for which this version exists.

**Done when:** `./scripts/build-brand-assets.sh` succeeds and
`data/brand/reprise-stats-symbolic.svg` plus
`data/icons/hicolor/symbolic/apps/reprise-stats-symbolic.svg` contain the new
geometry (with `currentColor` replaced by `#222222`).

### Task 2 — Embed both application symbolics in the GResource

**Files:** `scripts/build-brand-assets.sh`,
`crates/reprise-gnome/resources/reprise.gresource.xml`

In `build_surface_tree`, beside the existing copies to `$icons/symbolic/apps/`,
place one more copy of each file under
`crates/reprise-gnome/resources/icons/scalable/actions/`: one for
`reprise-stats-symbolic.svg` and one for `reprise-radio-symbolic.svg`. The path
must run through `target()` or `$tree_root` so that `--check` creates the files
inside the temporary tree. The generic comparison block at the end of the
script will then pick up the new files automatically.

Add a short comment at the copy site explaining the two copies. The hicolor
copy is the installation; the GResource copy is what an uninstalled run draws.
Without it, the app silently uses the system fallback.

Add both files beside the existing `icons/scalable/actions/` entries in
`reprise.gresource.xml`.

**Done when:** `./scripts/build-brand-assets.sh --check` is green and both SVGs
exist under `crates/reprise-gnome/resources/icons/scalable/actions/`.

### Task 3 — Remove the fallbacks that create the mistaken identity

**File:** `crates/reprise-gnome/src/ui/sidebar/sidebar_presentation.rs`

Remove the `fallback_icon_name` match arms for `Self::MyStats` and
`Self::Radio`, so both reach `_ => self.icon_name()` like `LYRICS` and
`VISUAL_BARS`, which the application also ships itself and which have no
fallback.

Record the reason in a comment: a safety net that shows the Queue or Music
symbol when it fails is worse than a visible Missing Image box because users
read the mistaken identity as intentional design. An embedded icon does not
have this failure mode anyway.

Update the tests in the same file (around lines 429–440 and 763):
`NavIcon::MyStats.fallback_icon_name()` and
`NavIcon::Radio.fallback_icon_name()` must now return their own names.
`Self::Concerts` and `Self::LibraryDoctor` remain unchanged.

**Done when:** `cargo test -p reprise-gnome sidebar_presentation` is green.

### Task 4 — Tighten the icon guard

**File:** `crates/reprise-gnome/src/ui/icons.rs`

- Remove the `GUARDED` entries for `reprise-stats-symbolic` and
  `reprise-radio-symbolic`. They mean “this system cannot draw the name”; after
  Task 2 it can. A guard that continues to apply would mask exactly the
  regression this plan removes. Keep
  `io.github.marvinbaudach.Reprise-first-aid-symbolic`,
  `external-link-symbolic`, and `ticket-symbolic`.
- Extend `private_symbolics_are_embedded_at_icon_theme_paths` with the two new
  names. Note that the assertion currently requires `starts_with(b"<?xml")`,
  while the brand-generated files start with
  `<!-- Generated by scripts/build-brand-assets.sh. … -->`. Reshape the
  assertion so it accepts both origins, for example by checking that the data
  contains `<svg` and ends in `</svg>\n`, without weakening its purpose: it
  must still catch empty or truncated resources.

**Done when:**
`xvfb-run -a cargo test -p reprise-gnome -- --ignored icons::tests` is green,
especially `every_icon_name_the_app_asks_for_can_be_drawn` and
`private_symbolics_are_embedded_at_icon_theme_paths`.

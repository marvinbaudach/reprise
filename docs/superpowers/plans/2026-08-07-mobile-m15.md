# M15 — a sidecar belongs to a track, or it does not belong

M14 shipped and the hardware pass confirmed its claim: a phone holding 214
tracks went from 20 analysis sidecars to **214**, with no track left without one
and no audio recopied. The 194 that had been stranded got their analyses.

The same pass then found two things M14 introduced, and a third the follow-up
review found.

## 1. Sidecars are planned for tracks that are not there

`crates/reprise-core/src/device_sync/mirror.rs:322`:

```rust
for desired in &plan.desired_files {
```

The planning walks the **desired** set — the selection — not what is on the
device. M14's plan said *track on the device, sidecar absent → copy the sidecar*;
what was built is *track selected*. Those agree only while the audio actually
arrives.

On the real phone they disagreed by exactly 77: 291 sidecars against 214 tracks,
and 291 − 214 = 77 sidecars whose audio never landed.

A sidecar for a track being copied **in this same run** is fine — the audio
follows it. A sidecar for a track that is neither resident nor being copied is
not.

## 2. Nothing will ever remove them

M14 made sidecars exempt from orphan removal so the desktop would not delete
them merely for not being audio. That was right, and it was stated too broadly:
**"not removable because of its extension" became "not removable".**

A sidecar whose track is absent from the device *is* an orphan. It is the one
thing that can never be useful again — nothing on the phone will ever read it,
because the audio it describes is not there.

The 291 sidecars occupy 32.2 MB on the device, of which roughly 8 MB describe
tracks the phone does not have.

The metadata list is a different case and stays exempt: it belongs to the device,
not to any one track.

## 3. One byte total still counts sidecars as music

`crates/reprise-gnome/src/ui/device_sync/device_sync_runtime.rs:241`, inside
`DeviceState::view()`, still calls `category_bytes(&self.managed_files)`
unfiltered. The two call sites M14 fixed cover the persisted value and the
post-verification snapshot; this one feeds the **visible** "*X* on device" row in
the content panel. The bug M14 set out to close is still on screen on that one
path.

## Proof

Every fix mutation-proven: break it, show the real red, restore it, show green.
A test that also passes without the fix does not count.

The device state that found this is the test: a selection larger than what fits
on the device, so that some desired tracks have no audio there. Today that plans
a sidecar for every one of them; it must plan sidecars only for tracks that are
resident or arriving.

Cover also: a sidecar whose track is absent is planned for removal; a sidecar
whose track is present is not; the metadata list is never removed; and the
content panel's "on device" figure excludes sidecar and metadata bytes.

## Verification

The nine gates, plus the seven display-gated `device_sync` tests run

display-gated), **136 platform-linux**, **153 JVM tests in 33 classes**.

## The pass that found this

Repeat it on hardware: after a sync, every sidecar on the device must have its
track beside it, and every track its sidecar. Both directions, counted.

# M9b — the screen you look at from a metre away

Follows M9a, which gave the app a ViewModel, a `WindowSizeClass` rule and its
landscape layouts. This package builds the Now Playing surface that landscape
makes worth having: **dock mode**, the **ambient visualiser**, and the **switch**
between visualisers.

Design source: frames **17b** (dock) and **11d** (ambient), plus the brief of
2026-08-05 and its amendments of the same night.

The settings screen is M9c. The seek bar and the two data-driven visualisers —
spectrum at the cover, and the preview band — need the spectrogram that S1 is
building; they are in neither.

## One value, one control

The owner settled this and it governs the whole package:

> A favourite **is** a rating of five. No second field, no heart flag. In any one
> place there is **always only one representation of that value** — a heart and
> stars side by side would be two controls for one thing, and they can
> contradict each other.

Where that lands:

| place | control |
| --- | --- |
| Now Playing, portrait and landscape | the five stars, tappable |
| library rows | stars **only if switched on** in Darstellung — otherwise nothing |
| dock mode | a **single star, 64 dp** |

M9a already applied the first row: the landscape transport carries no separate
favourite button, because the rating row is in the same column. The library-row
toggle belongs to the settings screen and arrives with M9c — until then those
rows stay as they are.

**Dock mode's single star is this package's job**, and its behaviour is settled
too: filled means rating five; tapping sets five; tapping again **restores the
previous value**. That is the answer to a question that has no other good one —
zero would throw away a rating the listener chose, four would invent one they
never gave. Restoring what was there destroys nothing, and it means the control
has to remember what it replaced. Decide where that memory lives and what
happens to it when the track changes or dock mode is left; a remembered value
that outlives its track would put the wrong rating back.

The reason for one big star rather than five small ones is in the brief: **five
separate stars are not hittable from a metre away.** Same value, coarser control.

## 1. Ambient

Replaces the cover surface. No bars, **and no pulsing**.

Three soft colour fields taken from the cover's own colours, blurred **30 dp**,
drifting on offset periods of **13 / 19 / 24 s**. Purely time-driven: the
playback snapshot carries no level, and an audio tap is ruled out — so nothing
here claims to be listening. Background is **true black**, which on OLED costs
almost nothing and is the reason it is black rather than merely dark.

Establish where the cover's colours come from — whether `androidx.palette` is
available, or whether the artwork the app already decodes can yield them without
a new dependency. Say which you chose and what it costs, because it runs on every
track change.

## 2. Switching

The choice is **Cover · Spektrum · Vorschauband · Ambient** — four entries,
**identical in the bar and in the long-press menu**. "Cover" is the left entry
and returns to the unchanged album cover; it is what used to be the lyrics
toggle, and lyrics are out of scope.

A long press on the visualiser surface opens an M3 `DropdownMenu` **anchored at
the touch**, four radio rows, haptics on open, the selection closes it
immediately, and the surface crossfades over **120 ms**.

**Spektrum and Vorschauband are shown and disabled**, because their data does not
exist yet. That is not an invention: the brief prescribes exactly this state for
a track without analysis — *"flacher Slider, Visualizer ausgegraut"*. A disabled
row that explains itself in one line beats an absent one, because absent looks
like a bug and disabled looks like a plan.

The stored choice **survives restarts and applies across tracks**, not per album.
M5 established how a shared setting is read and written without stealing a value
it did not author; follow that shape. The same choice appears in the settings
screen (M9c) and both must write one value.

## 3. Dock mode

Frame 17b. For a car mount and a desk — the actual reason a phone lies sideways.

The measure is **a glance from a metre and a hand that does not look**:

| element | size |
| --- | --- |
| play | 96 dp |
| previous / next | 76 dp each |
| title | 46 dp |
| artist | 22 dp |
| cover | 290 dp, left |

**Left out:** navigation, the rating row, play counts, volume.
**Kept:** previous, next, pause, the single star, exit.

Background true black with the ambient fields from 11d — nearly free on OLED, and
nothing glares in a dark car. Clock top right, otherwise no system bars
(immersive).

**It never turns itself on.** On rotating into landscape, show a small
**"Dock-Modus"** button briefly; offer *"beim Laden im Querformat automatisch"*
in the settings. A mode that switches itself on annoys everyone who merely held a
video crooked.

**`FLAG_KEEP_SCREEN_ON` only while docked** — and prove it is released on every
way out, including the one where the activity is destroyed rather than the mode
exited.

## 4. The performance rules that bind here

- **Stop drawing in the background and with the screen off.** A full-screen
  visualiser still running in a pocket is the shortest path to bad reviews. Prove
  it stops with a test that asserts the animation is not scheduled — not a
  comment claiming it.
- **Respect the system's "animations off".** Then the ambient drift is gone and
  the surface is static.

## Proof

Every test mutation-proven: break it, show the real red output, restore it, show
green.

M7's warning binds: a Robolectric test that wires a composable directly and never
enters the activity's path can stay green while a device fails. M9a's tests
already run `MainActivity.onCreate`, the real service bind and
`ActivityScenario.recreate` — follow that, and say which path each test runs.
Claims about immersive mode, the screen-on flag and a long-press menu are
lifecycle claims; they belong on the real path.

## Verification

The standard seven gates, each exit code captured on its own, never through a
pipe; the results directory deleted before the Gradle run and every `TEST-*.xml`
mtime compared against the run's start. `crates/reprise-gnome`: **zero lines**.

The theme lint fails the build if a raw Compose colour appears outside the theme
file. True black and the ambient fields are colours — here that is a real
constraint, not a formality.

## Nothing on the owner's screen — absolute

No emulator, no `adb`, no launching the app, nothing in the foreground. The
device pass is mine, and this package leans on it more than most: immersive mode,
the screen-on flag and a long-press menu are things a JVM test can only
approximate.
